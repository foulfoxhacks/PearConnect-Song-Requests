## Validation

- Original smoke file remains unchanged and fingerprint-checked: 12 assertions.
- Node regression suite: 73 tests, including loopback HTTP/WebSocket, malformed inputs, identity handling, reconnect/deduplication, moderation, uncertain writes, lifecycle transitions, rule persistence and instance exclusion.
- Windows C# contract harness: 17 assertions plus actual HTTP payload and mutation-count checks. Generated five-action import remains byte-consistent with its source.
- Actual hidden Electron window: sandbox/context isolation, no Node/raw IPC exposure, sender validation, permitted/rejected operations, forms, plain-text rendering of hostile markup, no page overflow, OS-encrypted settings, real local authorization against a fake player and independent CLI exclusion.
- Portable Windows x64 build with bundled runtime. Archive checked for accidental `.env`, credentials, Git metadata or Electron development dependencies.
- Dependency audit: zero known vulnerabilities at local validation time, including desktop build dependencies.

No live TikTok, Twitch or YouTube account, actual Pear Desktop playback, or Streamer.bot desktop import was used. Real local sockets and Electron/Windows cryptography were exercised; player and chat payloads were controlled test fixtures.

## Release feedback

Ship this as **0.3.0-beta.1**, with Desktop + Simple as the new-user preview and Advanced migration preserved. Before promoting it to stable, complete the target-machine checklist in [DESKTOP.md](DESKTOP.md): capture real sanitized TikFinity events, confirm actual player authorization/queue behavior, test fresh-machine onboarding and measure a streaming workload. The Windows build is portable and unsigned.

The third release from the design remains future work: persistent history, reconciled queue ownership, approvals, cancel/remove/reorder and overlays. Current history is session-only and bounded. Per-user request counts remain a duration approximation. Simple replies remain in PearConnect; no unverified TikTok write channel is advertised. Attach-to-running-engine is not available: second engines clearly refuse startup.

References checked during implementation: [TikFinity event API](https://tikfinity.zerody.one/tiktok/dapi), its referenced [connector events](https://github.com/zerodytrash/TikTok-Live-Connector#events), [Streamer.bot integration](https://tikfinity.zerody.one/streamerbot-integration), and Electron’s [security](https://www.electronjs.org/docs/latest/tutorial/security) and [credential storage](https://www.electronjs.org/docs/latest/api/safe-storage) documentation.
